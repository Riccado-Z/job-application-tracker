# 本工作区的硬性约束

## 1. 删除操作必须事先获得用户明确确认

**任何删除、覆盖、清空、重置数据的操作，动手前必须先问用户并得到明确同意。** 包括但不限于：

- `Remove-Item` / `del` / `rm` / `os.remove` / `shutil.rmtree`
- 移动或重命名用户的数据文件（等价于让原路径消失）
- 覆盖写入已有内容的文件
- 清空表格行、清空数据库、`/api/rebuild` 之类的重置接口

未获确认前不得执行。即使用户在同一句话里要求了别的任务，也不能顺带删除。

**背景**：2026-09-14，agent 在未确认文件内容的情况下执行
`Remove-Item E:\秋招\投递管理\投递记录.xlsx`，删除了用户的求职投递记录。
`Remove-Item` 不进回收站，数据无法恢复。这个教训必须记住。

## 2. 清理测试产物前，先确认它确实是测试产物

正确流程：

1. 先**读**文件内容并打印出来
2. 确认里面**全部**是本轮自己生成的测试数据
3. 再做一次自动快照 / 备份
4. 然后才删

本项目里 `tests/_selftest.py`、`tests/_locktest.py` 会写真实数据，
已内置安全闸：表里非空时会拒绝运行（退出码 3）。不要绕过它，
也不要用 `QP_TEST_FORCE=1` 强行运行真实数据的表。
**要跑自检，请先复制整个 `投递管理` 文件夹，在副本里跑。**

## 3. 数据文件与备份位置

- 真实数据：`E:\秋招\投递管理\投递记录.xlsx`
- 自动快照：`E:\秋招\投递管理\backups\`（每次写入前自动生成，保留 400 份）
- 软删除记录：Excel 里的 `已删除` 工作表（删除的记录不销毁）
- 恢复入口：网页「🛟 回收站与历史版本」面板

这些保护是给用户兜底的，**不是 agent 可以随意删除数据的许可**。
